# Testing guide
`npm test` (Vitest, real Postgres `TEST_DATABASE_URL`): `matching.test.ts` (21, pure engine), `identity.test.ts` (11), `marketplace.test.ts` (21: posting rules, application workflow, ownership/cross-account checks, DB matching, talent privacy, audit immutability, transaction rollback), `admin.test.ts` (10: RBAC matrix, service-level permission enforcement, suspension, moderation, verification, versioned rules), `phase2b.test.ts` (16: screening questions, notification email + opt-outs + throttle + no message text, SMTP delivery against a local SMTP server incl. honest failure, file validation, attachment access control, admin report queue/audit/resolution, review reports), `phase2.test.ts` (16: shortlist/invitations, messaging access + contact guard + rate limit, assignment lifecycle and access control, blind reviews and ratings). `node tests/e2e/journey.mjs` runs a 20-step Playwright journey (worker register→verify→onboard→recommend→apply→save; business post/validation/pipeline/offer→worker accept→filled; message with file attachment (download allowed for participants, 404 for anonymous/unrelated users, forced attachment) → report → moderator resolves (access ends, audited) → settings persist → screening question answered; message → submit hours → approve → blind review (hidden then revealed, worker sees only "First L." on the business side); talent privacy; cross-business 404; admin dashboard/suspend/audit/RBAC/rules; mobile 390px no horizontal scroll) against a built app (`next start -p 3100`, seeded DB, `BASE_URL` to override).
**Not covered:** password-reset and logout through the browser, tablet viewport, automated accessibility audit (axe), load/performance, payments (not built), file upload security (not built). Manual WCAG 2.2 AA verification has **not** been performed; contrast tokens were chosen for AA but not measured.
