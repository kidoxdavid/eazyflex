# Testing guide
`npm test` (Vitest, real Postgres `TEST_DATABASE_URL`): `matching.test.ts` (21, pure engine), `identity.test.ts` (11), `marketplace.test.ts` (21: posting rules, application workflow, ownership/cross-account checks, DB matching, talent privacy, audit immutability, transaction rollback), `admin.test.ts` (10: RBAC matrix, service-level permission enforcement, suspension, moderation, verification, versioned rules), `team.test.ts` (15: joining by registration/acceptance, token rules, role matrix across every write path, cross-business isolation, role changes/removal/leaving, DB invariants), `recurring-engine.test.ts` (13: date maths, occurrence generation, term/renewal rules), `recurring.test.ts` (13: sessions, logging/confirming/missing/cancelling, term end, renewal offers incl. explicit acceptance and expiry, reminder job), `regressions.test.ts` (3), `coverage-engine.test.ts` (19: window arithmetic, gap/overlap/outside-demand analysis, 30 h across four part-timers, never outside availability, weekly cap, commitments, determinism, handover detection), `coverage.test.ts` (14: suggest/propose/confirm lifecycle, discoverability and skill eligibility, atomic batches, explicit-agreement rules, cross-opportunity clash incl. confirm-time re-check, access control, release, handovers), `saved-searches.test.ts` (6: validation, isolation, digest behaviour, baseline reset, suspended users, email preference), `phase2b.test.ts` (16: screening questions, notification email + opt-outs + throttle + no message text, SMTP delivery against a local SMTP server incl. honest failure, file validation, attachment access control, admin report queue/audit/resolution, review reports), `phase2.test.ts` (16: shortlist/invitations, messaging access + contact guard + rate limit, assignment lifecycle and access control, blind reviews and ratings). `node tests/e2e/journey.mjs` runs a 24-step Playwright journey (worker register→verify→onboard→recommend→apply→save; business post/validation/pipeline/offer→worker accept→filled; work-sharing end to end (suggest → propose → four workers confirm → 100% → handover note + acknowledge → release reopens the gap → other business gets 404), team invite → join via link → member blocked server-side → owner removes member; recurring accept → cancel a session → renewal offer → worker accepts → end term → reviews; saved search save/toggle/delete; message with file attachment (download allowed for participants, 404 for anonymous/unrelated users, forced attachment) → report → moderator resolves (access ends, audited) → settings persist → screening question answered; message → submit hours → approve → blind review (hidden then revealed, worker sees only "First L." on the business side); talent privacy; cross-business 404; admin dashboard/suspend/audit/RBAC/rules; mobile 390px no horizontal scroll) against a built app (`next start -p 3100`, seeded DB, `BASE_URL` to override).
**Not covered:** password-reset and logout through the browser, tablet viewport, automated accessibility audit (axe), load/performance, payments (not built), file upload security (not built). Manual WCAG 2.2 AA verification has **not** been performed; contrast tokens were chosen for AA but not measured.
