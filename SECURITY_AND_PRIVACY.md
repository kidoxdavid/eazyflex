# Security and privacy (implemented vs not)
**Implemented:** argon2id passwords (≥10 chars, letters+number); hashed single-use verification/reset tokens with expiry; verification is a POST (prevents link-scanner consumption); generic login/reset responses; constant-ish time for unknown emails; DB-backed rate limits (login per email/IP, reset per email); sessions hashed at rest, httpOnly+SameSite cookie, revoked on reset/suspension; server-side authorisation in services + route guards; Zod validation everywhere; parameterised queries (Drizzle) — one raw-SQL helper is parameterised; React output escaping, JSON-LD escapes `<`; open-redirect guard on `next`; security headers (nosniff, frame deny, referrer, permissions-policy); append-only audit log; messaging limited to participants with an existing relationship, contact-detail guard and rate limit, workers shown to businesses as "First L."; assignment/message/review access returns not-found to outsiders and role cannot be spoofed; blind reviews (anti-retaliation); worker privacy (businesses see "First L.", skills, area, availability — never email/phone/address; opt-in `public_profile`; approximate areas only); no SIN/bank/card/ID-document collection; postal code limited to the first 3 characters; consent records with policy versions; "unverified" never shown as verified.
**Team access:** role checks in the service layer on every business write (members cannot post, hire, edit the profile, manage coverage/renewals or review); invitation tokens hashed, single-use, expiring, bound to the invited email; DB-enforced single owner and single business per person; removal takes effect immediately (no session reload needed). **Uploads (implemented):** extension allow-list + magic-byte check, size/count limits, random private keys, authorised same-origin download route (no public/signed URLs), forced attachment + nosniff + sandbox CSP, admin access only to reported content and audited. **Not implemented / required before launch:** global CSP header, malware scanning (files are marked `unscanned`), S3-compatible private storage driver (only local disk exists), virus-scan quarantine, encryption-at-rest configuration (infra), secrets manager, account deletion & data export workflows (PIPEDA/PIPA), backups/DR runbook, email-sending SPF/DKIM and CASL consent flows, password-breach checks, MFA (esp. admin), admin sensitive-access logging for messages/documents (none exist yet), penetration test, a non-owner DB role (so audit triggers can't be dropped), distributed rate limiting at the edge, legal review (Alberta employment standards, agency licensing, classification, OHS, WCB, insurance, tax, background checks, vulnerable-sector screening).
