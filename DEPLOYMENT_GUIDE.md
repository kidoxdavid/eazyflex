# Deployment guide
Not yet deployed anywhere; no CI/CD exists. Suggested path: managed PostgreSQL (Canadian region), Node 22 host or container for `next build && next start`, run `npm run db:migrate` as a release step, set env vars (below), serve behind HTTPS (cookies are `Secure` in production). **Email:** set `EMAIL_DRIVER=smtp`, `SMTP_URL`, `EMAIL_FROM` and run `npm run emails:send` every minute or so (cron/scheduler) — there is no in-process queue. **Operations:** see RUNBOOK.md (health/readiness endpoints, logs, error reporting, scheduled jobs, backups, restore drill, incident response, secret rotation), THREAT_MODEL.md and LAUNCH_CHECKLIST.md. **Secrets & security:** set `APP_SECRET` (≥ 32 random chars; the app refuses to use TOTP in production without it), serve only over HTTPS with `APP_URL=https://…` (enables `upgrade-insecure-requests`, HSTS, the `__Host-` cookie), keep `MFA_ENFORCEMENT` at its production default, and enrol every admin at first sign-in (their recovery codes appear once). Define a backup retention window — deleted accounts persist in backups until they roll off. **CI:** `.github/workflows/ci.yml` runs typecheck, a migration-drift check, the Vitest suite, a production build, `npm audit` (high+), then the browser journey + keyboard + axe audit via `scripts/e2e.sh`. It has not been executed on GitHub from this environment; the same commands were run locally. **Jobs:** schedule `npm run renewals:run` daily (renewal reminders/expiry, rolling sessions). **Alerts:** schedule `npm run alerts:send` (e.g. daily or hourly) — nothing runs it automatically. **Storage:** `STORAGE_DIR` must be a persistent private volume (local driver only; add S3-compatible storage for multi-instance deployments). **Before launch you must:** verify SPF/DKIM for the sending domain, run the app as a non-owner DB role, add backups, monitoring (Sentry), CSP, and complete legal/privacy review. Never run `db:seed`/`db:reset` against production (both refuse when `NODE_ENV=production`, but do not rely on that alone).
